{# Every patchable element on the L4 OPCPA page. One macro per widget `macro` name in `modules/l4_opcpa/widgets.py`. Each takes `id` and `show` (the Datastar expression for an expandable region, or none) plus whatever its context builder produced. Two rules hold throughout: * The element carries the `id` the SSE patch targets, so the markup rendered into the page and the markup pushed later are byte-identical. * Colour is never chosen here. A macro emits `data-tone-surface` ("I am the element that paints") and `data-tone` ("this is the tone"), and the tone layer in `static/css/hmi.css` decides what that looks like. A template that picked its own red would be a second, competing notion of "bad" — which is the bug the tone layer exists to make impossible. #} {%- macro _tone(readout) -%} {%- if readout.tone %} data-tone="{{ readout.tone }}"{% endif -%} {%- if readout.title %} title="{{ readout.title }}"{% endif -%} {%- endmacro -%} {#- `data-show` plus an inline `display:none`. The inline style is what the server can honestly assert: every expandable region starts closed. Without it the list is visible for the moment between the HTML parsing and Datastar initialising — with a 22-row module-error list per laser, that flash is worse than any cost of the style attribute. On a later patch the element may in fact be open. Datastar's show plugin watches the `style` attribute and re-evaluates when it changes, so the incoming `display:none` is corrected on the same frame it lands. -#} {%- macro _show(show) -%} {%- if show %} data-show="{{ show }}" style="display:none"{% endif -%} {%- endmacro -%} {#- The text of one reading.
