{# Row layout and section chrome — the static half of a screen. None of this is ever patched. It is rendered once with the page and then lives entirely in the browser, because it is the half the operator *interacts* with: a cog panel that is open, a half-typed setpoint, a selected choice. An SSE patch landing here would close panels and eat keystrokes, so a component's widgets deliberately stop at the value cell (`{{ w['…'] }}` below). A component template usually needs only two of these: {% import "rows.html" as rows with context %} {{ rows.card() }} … {{ rows.endcard() }} a section box {{ rows.row(c.label, w['value'], actions) }} one labelled row #} {% import "controls.html" as controls with context %} {#- A section box. Rows inside it share one label-column width, which is what keeps a column of readings aligned. -#} {%- macro card_open() -%}
{%- endmacro -%} {%- macro card_close() -%}
{%- endmacro -%} {#- The standard row: label, value, optional action slot. `value` is already-rendered widget HTML. `bare` is for a value that carries its own chrome (a pill), where a bordered cell around it would be a box inside a box. `wide` widens the value field for a row that carries more than a reading — two channels in one cell, a long waveform name. Values are otherwise all one width, which is what lets a card be scanned down its column rather than read line by line, so reach for this only when the content needs it. -#} {%- macro row(label, value, action=none, bare=false, wide=false) -%}
